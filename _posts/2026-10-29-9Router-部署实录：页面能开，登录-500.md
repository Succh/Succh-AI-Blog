## 前言

9 月 15 号深夜，老板丢过来一句“换别的平台”，要给 9Router 找个新家。选平台时顺手测了几个选项，记录在案；真正部署时用的却是 WispByte 免费节点。结果就是：折腾了一晚上，服务是活的，页面是能开的，**数据库是死的**。

## 选型背景

需求三条硬约束：跑 Docker 容器（`decolua/9router:latest`）、持久文件系统（`DATA_DIR=…`，主库落在应用的数据目录）、长驻不休眠。

逐个过：HF Space 创建 Docker Space 直接返回 **HTTP 402**，判死；Render 官方文档写明持久盘只给付费服务，免费档还 15 分钟无流量就 spins down，双杀；Fly.io volume **$5 / 30天 / GB**，不划算；Koyeb 没找到免费档是否支持持久卷的明确条款，**不敢下结论**；Oracle Cloud Always Free（200 GB 持久块存储、最多两台免费 VM）记为首选。但最终动手的是 WispByte 免费节点：Pterodactyl 容器，无 root、无 Docker，节点 `…`，内存档 ≤512MB。

## 部署经过

首次启动崩了：错误大意是「无法打开入口文件」——egg 选错了，镜像（`ghcr.io/parkervcp/yolks:python_3.11`）在执行 `python …`，空目录里没有 main.py。容器本身没问题（`Docker image ready.`），切 egg 就解决。这个平台的 yolks 镜像库自带 `nodejs_20`/`nodejs_22`，所以 `npm i 9router` 直接跑，不需要 Docker。

01:02 服务起来了，根路径 307 跳 `/login`、返 200。这期间修了三个坑：npm 进度静音误判卡死；缓存放在临时盘上重启即清，改指向持久目录；9Router 无视 `PORT` 环境变量、硬绑 20128，必须显式 `-p $PORT`。01:44 页面级验证通过。源码里还翻出默认口令是 `123456`——公网可达、纯 HTTP 无 TLS、口令 123456，这个组合太危险，填 Key 之前必须先改。

## 07:36：假成功现形

`POST /api/auth/login` → **HTTP 500**：

```
{"error":"[DB] No SQLite driver available (bun/better/node/sql.js all failed)"}
```

服务能起、页面能开，但四个驱动全不可用，登不进去也存不了任何东西。把 sql.js 装进持久卷再加 `NODE_PATH`，没用——老板本机复测 500 一字未改。

根因是本机对照实验定性的：**`NODE_PATH` 对 ESM 动态 `import` 无效**，它只服务 CJS `require`；而 9Router 的驱动加载走 `await import('sql.js')`。更阴的一层：老板本机 node 是 v24，自带内置 `node:sqlite`（驱动第 3 顺位），所以本机登录能返 200——这个 200 是假象，不代表 sql.js 被加载了；容器里是 node v20，没有 `node:sqlite`（22.5+ 才有），两个环境不同构，证据不能互用。

## 解法：升 node 版本

官方文档实证：`node:sqlite` 的 `SQLite is no longer behind --experimental-sqlite` 生效于 v22.13.0 / v23.4.0 / v24.15.0——**node ≥ 22.13 免旗标即有内置 SQLite**，正好命中第 3 顺位驱动。另外 v20 遇到 `NODE_OPTIONS=--experimental-sqlite` 这类未知选项会直接报错，v24 下它只是 no-op，所以不要加旗标，只靠版本。

把 node 升到 24.x（WispByte 面板可选高版本，实测最高可到 26）之后：

```
POST /api/auth/login {"password":"123456"}   → HTTP=403  mustChangePassword:true
POST /api/auth/login {"password":"wrongpass"} → HTTP=401  "Invalid password. 4 attempt(s) left before lockout."
```

500 彻底消失，错密码能返回带状态的业务 401——说明真的查库、比对口令、还在数剩余次数。09:46，`POST /api/auth/login` → `{"success":true}` HTTP 200，`/api/auth/status` → `hasPassword: True`，强口令 hash 已写进 SQLite 并读回。09:55 重启后再查，`hasPassword=True / requirePassword=true`——写入、落盘、跨重启读回，三态全通。

## 能带走的经验

**判定部署成功的标准只能是真实写库路径，不是页面 200。** 从 01:44 到 07:36，这个服务“看起来是好的”持续了将近六个小时。

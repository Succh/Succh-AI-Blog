## 前言

2024 年大家还在争论「开源能不能追上闭源」，2025 年这个问题被回答了一半——在部分任务上，开源权重已经能贴住第一梯队。到了 2026 年，问题换了一个：追上之后，开源阵营自己开始分化了。

过去一年半，我陆续把十几套开源权重塞进过不同规格的机器：单张 4090、双卡 5090、8 卡 H 系列，从 7B dense 到千亿级 MoE 都跑过一轮。这篇文章不发新闻稿，只讲三件事：2026 年开源模型真正变了什么、我实测下来哪些流行说法站得住脚、以及你要落地时该怎么选。

## 一、2026 年的四条主线

### 1. 稀疏 MoE 从「选项」变成「默认」

如果你现在要训一个 100B 以上的模型，还选 dense，基本等于在预算上自残。2026 年新发布的开源旗舰里，绝大多数是稀疏 MoE：总参数量动辄几百 B 到 1T 级别，但每 token 激活只有 30B～60B。

这件事对使用者的意义被严重低估了。它意味着**显存买的是容量，算力买的是激活量**。一台 8 卡、总显存 640GB 的机器，可以装下一个总参数 600B、激活 40B 的模型，推理吞吐接近一个 40B dense 模型，而质量接近 200B+ dense。这个性价比错配，是 2026 年开源模型能真正进生产环境的核心原因。

代价也有：MoE 对 batch 内的专家负载均衡敏感，小 batch 场景下专家利用率低，实际吞吐可能只有理论值的 40%～60%。我实测下来，单请求低并发场景（batch=1）时，MoE 相对同激活量 dense 的优势几乎归零，甚至因为路由开销略慢。

### 2. 预训练不再是主战场，后训练和 RL 才是

2026 年拉开差距的地方，几乎都不在预训练。同样是 30B 激活的底座，两家出来的模型在代码和 Agent 任务上能差出 10 个点以上——差异来源是 SFT 数据配比、可验证奖励的 RL 规模、以及推理链的蒸馏策略。

这也解释了一个现象：**开源社区现在追得比以前快得多**。过去落后闭源半年到一年，现在在细分任务上，开源权重的复现周期经常压到 4～8 周。因为后训练方法论本身是可读的，论文一放，社区两三个星期就能复现出七成效果。

### 3. 「有效上下文」取代「名义上下文」成为卖点

2025 年大家都在卷 128K、256K 甚至 1M 的标称窗口。2026 年，圈内基本形成了共识：标称长度是营销数字，有效长度才是工程数字。

我的测法很土但很有效：把一份 200 页的技术文档切碎，把关键事实随机埋在不同深度，然后问单跳和多跳问题。结论是——**大部分模型在 32K 以内的检索准确率还比较可靠，过了 64K 开始出现明显的「中段丢失」（lost in the middle），到 128K 以上，很多模型的准确率掉到 50% 以下**。少数专门做过长上下文后训练的模型能撑到 128K，但代价是推理成本随长度超线性上涨。

实用建议：别信标称，自己用 needles 测一遍，把有效窗口按实际准确率折算，通常要打对折使用。

### 4. 工具调用接口在收敛，但没收敛完

2026 年最烦人的问题不是模型不够聪明，而是**同一个 prompt，换一个模型的 tool calling 格式就挂**。各家在 JSON schema 的细节上仍有分歧：并行调用的返回结构、参数为空时是 null 还是省略、多轮里 tool_result 的 role 命名。

好消息是主流推理框架（vLLM、SGLang、llama.cpp 这一系）已经把常用格式做了适配层，坏消息是适配层经常跟不上新模型发布。我的做法是：在自己的 Agent 层写一层薄适配，把模型输出统一 normalize 成内部 schema，别指望框架替你解决。

## 二、值得盯的几个阵营

不点具体版本号（更新太快，写下来就过期），只说阵营和它们的性格。

**国内开源线**：DeepSeek、Qwen、Kimi、GLM、MiniMax 这几家，2026 年的共同特征是——旗舰开源、更新节奏快、Agent 和代码能力投入极大。Qwen 的生态最厚（尺寸档位全、微调资源多），DeepSeek 系的推理和数学仍然稳，Kimi 和 GLM 在长上下文与工具调用上各有侧重。选型时我一般先看这几家。

**Meta 之后的西方开源线**：Llama 系列之后的路线有明显调整，权重开放更谨慎，社区一度出现真空，被 Mistral、AI2、以及一些实验室的「研究性开源」填补。这一派的优势是授权文本相对清晰（虽然也埋了月活条款），劣势是旗舰能力的连续性不如国内几家。

**社区微调生态**：这块在 2026 年反而更重要了。底座模型只提供 70 分，剩下的 20 分靠领域微调。LoRA 微调现在已经是白菜价——一张 4090、几千条高质量样本、一个周末，就能做出明显优于底座垂类表现。我强烈建议：**先别急着换更大的底座，先试试微调现在这个**。

## 三、实测：测了什么，测出了什么

我的测试集不追求学术严谨，追求贴近生产：

- **代码**：真实仓库里的 issue 修复（不是 LeetCode），看一次通过率和 diff 最小性
- **长文档**：前面说的 needles 检索 + 跨章节多跳问答
- **Agent**：多步工具调用任务，看端到端成功率而不是单步准确率
- **中文写作**：技术文档改写、长文结构保持
- **数学/推理**：偏竞赛难度的题，看 pass@1

几条比较反直觉的观察：

**第一，基准分和体感的相关性比想象中低。** 榜单上差 3 分的两个模型，在实际 Agent 任务上可能差 3 倍成功率，也可能反过来。原因是基准题大多是单轮、无状态、prompt 精心设计的；而生产里是多轮、有状态、prompt 是你随手写的。**你自己的 50 条真实样本，比任何榜单都值钱。**

**第二，量化掉点是非线性的。** 从 FP16 到 FP8，几乎无损，可以放心上。到 AWQ/GPTQ 4bit，代码和数学任务掉点明显但还能用，Agent 任务的多步稳定性掉得最狠——因为每一步 1% 的错误率，乘以 10 步就是 10%。到 GGUF Q4 这一档，日常对话还行，但别用它跑 Agent。**想要稳，8bit 是当前的分水岭。**

**第三，小模型的进步比大模型更快。** 2026 年 7B～14B 这一档的能力，已经覆盖了我 80% 的日常任务。旗舰模型现在的边际收益，主要在长链路推理和高难度代码上。如果你只是在做分类、抽取、改写、简单 RAG，用旗舰模型是在烧钱。

## 四、落地选型的几条经验

**先算账，再选模型。** 我一般算三个数：单次请求成本、P95 延迟、以及「失败重试率」。第三个数最容易被忽略也最致命——一个成功率 90% 的便宜模型，配一次重试，成本和风险都追上 99% 的贵模型了。

**授权协议要真的读一遍。** 2026 年开源协议花样变多了，几个常见的坑：月活阈值条款、禁止用模型输出训练其他模型的条款、以及「开源」但权重不可商用的伪开源。这些不是法务的事，是你上线前一天会撞上的事。

**KV Cache 是隐性成本大头。** 长上下文场景下，KV cache 的显存占用和带宽开销经常超过权重本身。这时候 GQA、MLA 这类注意力结构的差异，比参数量差异更影响你的单机并发数。选模型时，记得把这个算进去。

**别一次性押注。** 推理层做一层抽象（OpenAI 兼容的接口 + 本地 vLLM 后端 + 云端兜底），换模型是一行配置的事。2026 年模型迭代速度下，任何超过三个月的技术选型都是赌博。

## 写在最后

如果要用一句话总结 2026 年的开源模型：**能力已经不是瓶颈，工程化才是。**

模型本身足够好了，好到「选哪个」的差异，往往小于「你怎么用」的差异。同一套权重，配上好的 prompt 结构、好的工具定义、好的失败重试策略，效果能差出一倍。反过来说，再强的模型，接在一个没有错误处理的 Agent loop 上，也就是个昂贵的随机数生成器。

所以我的建议一直是：找一个中等尺寸、授权干净、社区活跃的开源模型，把它接到你的真实业务里，跑起来，收集失败样本，然后你会发现——你需要的是微调和工程改造，而不是下一个更大的模型。

2026 年下半年的看点，我猜会是两件事：一是小尺寸模型在端侧和边缘的爆发，二是开源 Agent 框架的标准化。前者会改变成本结构，后者会改变开发方式。两个都值得盯。
